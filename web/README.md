# Offline configuration generator

Open [config.html](config.html) directly in a recent browser. This one file is
both the source and the distributable: no package installation, build, server,
CDN, external fonts or network requests. It uses native Web Crypto X25519 for
WireGuard keys; a browser without X25519 can still import and edit existing
configs but cannot generate keys or derive their public keys.

The page edits all current NodeSpec fields, including optional values and
explicit zeroes. It supports multiple nodes, paired static Peers, Fabric and
Domain routes/announcements, Babel, Dynamic Links and Durable policy. Routing
and Dynamic Links have separate controls. Static routes are entered explicitly
as destination prefixes and next-hop Peer aliases; paths are not auto-computed.

The two three-node presets reproduce `examples/static_minimal` and
`examples/dynamic_minimal`, generating fresh keys and UUIDs. Replace their
documentation endpoint addresses before deployment. Optional fields left blank
remain omitted; Peer ports can inherit node settings or explicitly override
them, including zero. A shared-parameter button copies Fabric keys/pools/VFP
port, while routes and table IDs remain per node.

Import one or several NodeSpec JSON files at once (or an array of NodeSpecs).
Import replaces the current set after confirmation. Direct JSON editing is
also available; unknown fields or wrong types are rejected without changing
the current config. Existing keys and optional fields are retained.

The page checks required fields, IPv4/IPv6 prefixes, ports, routes, source
overlap and selected cross-node constraints. Errors block export; warnings
cover situations such as example endpoints, missing reciprocal Peers and
different Babel modes. This is an editing aid; `velvetctl resolve` remains the
authoritative local validator, including derived resources. The page cannot
verify endpoint reachability, NAT mappings or installed executables.

Download one JSON or all nodes as a ZIP with unique filenames. The ZIP stores
Unix mode `0600`, but extractors and filesystem permissions vary. On each
target node, set the actual permissions and validate before starting:

```sh
chmod 600 node.json
velvetctl resolve --config node.json
```

Configs contain private keys and the shared Fabric PSK. They live only in page
memory until exported; nothing is saved to browser storage. Save before closing
or refreshing. Runtime observations and Durable agreements are not NodeSpec
and are not generated by this tool.

## Developer checks

There is no build step. The regression tests use Node's built-in test runner
(Node 22 or newer), without npm dependencies:

```sh
node --test tests/web/config.test.cjs
```

Tests compare both presets to the repository examples, check X25519 against a
known vector, validate representative errors and verify export bytes. To also
check generated JSON with the real Go validator, supply a built control client:

```sh
go build -o .local/bin/velvetctl ./cmd/velvetctl
VELVET_CONFIG_CTL="$PWD/.local/bin/velvetctl" node --test tests/web/config.test.cjs
```
